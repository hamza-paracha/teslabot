# Ten-minute interview walkthrough

Start with one question: **“Can I make the round trip?”** Follow the battery reading from MCP to the planner, then show how a telemetry event can update that same reading. The route distances come from the caller; TeslaBot supplies the vehicle data, not the route.

After `npm ci`, run `npm run demo`. It uses real application code, local D1 and a synthetic Tesla. Point out the stale refusal, the fresh reading after recovery, and the outbound request counts. The test links are pinned to the revision used to verify this walkthrough, so the links still land on the named tests if lines move.

## 8–10 minutes: questions to expect

- **Is ingest exactly once?** No. If some account writes fail, the Worker returns 503. The relay retries with the same batch ID, and the Worker skips accounts that already committed it. [The partial-commit test](https://github.com/hamza-paracha/teslabot/blob/e00598b10c793e2151cca985eb2ecd71bc6efdd9/tests/telemetry.test.ts#L438) proves that recovery path. A restart can still lose in-memory records.
- **What if a lease holder outlives 120 seconds?** A new holder can acquire the lease. The old holder cannot delete the new holder's lease, but the writes are not fenced. The concurrency test covers a normal burst, not expiry.
- **Why use both the lease and the budget?** The lease coalesces refreshes. The conditional reservation limits outgoing calls even when they do not share a refresh. These count local attempts and estimated spend, not the Tesla invoice.
- **Why not predict from the last reading or wake the car?** The old reading can be useful as labeled context, but it cannot answer whether the driver should leave now. Waking the car would change its state to answer a read-only question.
- **What did the replay actually prove?** [The fixture test](https://github.com/hamza-paracha/teslabot/blob/e00598b10c793e2151cca985eb2ecd71bc6efdd9/tests/telemetry-replay.test.ts#L5) checks expected readings and reminder counts after synthetic events, duplicates and omissions. It does not prove anything about live latency or restart recovery.
