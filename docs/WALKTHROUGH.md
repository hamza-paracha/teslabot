# Ten-minute interview walkthrough

Start with one question: **“Can I make the round trip?”** Follow the battery reading from MCP to the planner, then show how a telemetry event can update that same reading. The route distances come from the caller; TeslaBot supplies the vehicle data, not the route.

After `npm ci`, run `npm run demo`. It uses real application code, local D1 and a synthetic Tesla. Point out the stale refusal, the fresh reading after recovery, and the outbound request counts. The last phase sends a separate synthetic telemetry batch, fails one account's database write, and shows what happens on retry. The test links are pinned to the revision used to verify this walkthrough.

## 8–10 minutes: questions to expect

- **Is ingest exactly once?** No. If an account write fails, the Worker returns 503. The relay retries with the same batch ID, and the Worker skips an account if its last committed ID matches. [The partial-commit test](https://github.com/hamza-paracha/teslabot/blob/54dab29972209dfaeb010f4b223c72c5db6efcd7/tests/telemetry.test.ts#L567) proves that recovery path. A restart can still lose the in-flight batch and the queue.
- **What if a lease holder outlives 120 seconds?** Expiry lets another caller take over; expiry alone does not prevent writes. Once ownership is lost, the old Store's fenced batch fails instead of overwriting the new holder's data. In-flight Tesla requests are not cancelled. See [the takeover test](https://github.com/hamza-paracha/teslabot/blob/54dab29972209dfaeb010f4b223c72c5db6efcd7/tests/lease.test.ts#L19) and [the expiry-without-takeover test](https://github.com/hamza-paracha/teslabot/blob/54dab29972209dfaeb010f4b223c72c5db6efcd7/tests/lease.test.ts#L113).
- **Why use both the lease and the budget?** The lease coalesces refreshes. The conditional reservation limits outgoing calls even when they do not share a refresh. These count local attempts and estimated spend, not the Tesla invoice.
- **Why not predict from the last reading or wake the car?** The old reading can be useful as labeled context, but it cannot answer whether the driver should leave now. Waking the car would change its state to answer a read-only question.
- **What did the replay actually prove?** [The fixture test](https://github.com/hamza-paracha/teslabot/blob/54dab29972209dfaeb010f4b223c72c5db6efcd7/tests/telemetry-replay.test.ts#L11) checks expected readings and reminder counts after synthetic events, duplicates and omissions. It does not prove anything about live latency or restart recovery.

For the alternatives and when to change course, see the [decision records](adr/README.md).

## Backup questions: what changed and why

Use these if the interviewer wants to go deeper after the ten-minute slice.

- **#3 — Acknowledge committed telemetry.** Ingest used to return 200 even when an account write failed, so the relay moved on. Now `telemetryRoute` and `ingest` in [`src/routes/telemetry.ts`](../src/routes/telemetry.ts) return 503 for any failed account; `Forwarder.run` in [`relay.py`](../telemetry/container/relay.py) retries the same batch. The [partial-commit test](https://github.com/hamza-paracha/teslabot/blob/54dab29972209dfaeb010f4b223c72c5db6efcd7/tests/telemetry.test.ts#L567) checks the failed account recovers without rewriting the healthy account. **Does this make the queue durable?** No. The retry waits in memory, and waiting records can be dropped if the queue fills.
- **#4 — Give reminders stable delivery IDs.** A successful send followed by a failed status write could send the same reminder twice. Now `check` in [`src/scheduled.ts`](../src/scheduled.ts) claims a reminder occurrence in D1 before sending, and `sendNotification` in [`src/notify.ts`](../src/notify.ts) sends the ID as an `Idempotency-Key`. The [status-write failure test](https://github.com/hamza-paracha/teslabot/blob/54dab29972209dfaeb010f4b223c72c5db6efcd7/tests/alerts.test.ts#L155) proves the rerun does not post again. Apply [`0004_alert_deliveries.sql`](../migrations/0004_alert_deliveries.sql) before deploying. **What if the receiver accepts a request but the sender sees a failure?** The claim is released on send failure; a retry can still duplicate the send unless the receiver honors the same key.
- **#5 — Keep runtime and benchmark evidence in CI.** Unit tests alone did not exercise the Worker runtime, and benchmark results were local. [`ci.yml`](../.github/workflows/ci.yml) now runs [`workerd-smoke.ts`](../scripts/workerd-smoke.ts) and uploads the synthetic benchmark report. The [workerd smoke assertions](https://github.com/hamza-paracha/teslabot/blob/54dab29972209dfaeb010f4b223c72c5db6efcd7/scripts/workerd-smoke.ts#L31) exercise MCP and the scheduled handler without a live Tesla. **Is the reported latency a production promise?** No; the data is synthetic and the latency depends on the runner.
- **#6 — Replay by source time.** An old disconnect could mark a newer reading offline, and a newer 0 kW DC reading could be ignored. Open `telemetryOnline` and `applyTelemetry` in [`src/telemetry/mapping.ts`](../src/telemetry/mapping.ts). The [connectivity replay test](https://github.com/hamza-paracha/teslabot/blob/54dab29972209dfaeb010f4b223c72c5db6efcd7/tests/telemetry-replay.test.ts#L98) checks the order of readings and disconnects; the [AC/DC power test](https://github.com/hamza-paracha/teslabot/blob/54dab29972209dfaeb010f4b223c72c5db6efcd7/tests/telemetry.test.ts#L294) checks that a newer zero clears active DC power without clearing AC power. **Do all permutations converge?** Not if conflicting values have exactly the same timestamp: the first value for that field wins.
- **#7 — Put the failure demo first.** The README did not lead with one repeatable failure and recovery. Now `runScenario` in [`scripts/lib/demo.ts`](../scripts/lib/demo.ts) asks about the same saved trip online, asleep, and online again. The [trip timeline test](https://github.com/hamza-paracha/teslabot/blob/54dab29972209dfaeb010f4b223c72c5db6efcd7/tests/demo.test.ts#L23) checks the withheld answer, request counts and recovery. **Does it wake a real car?** No. The car is synthetic, and the asleep phase makes no wake or command call.
- **#8 — Keep credentials in scope.** A malformed Authorization header could fall back to a valid cookie, and the relay credential could read telemetry status. Open `authorize` in [`src/security/authorization.ts`](../src/security/authorization.ts) and `telemetryRoute` in [`src/routes/telemetry.ts`](../src/routes/telemetry.ts). The [bad-header test](https://github.com/hamza-paracha/teslabot/blob/54dab29972209dfaeb010f4b223c72c5db6efcd7/tests/credential-scopes.test.ts#L166) checks that a valid cookie cannot rescue an invalid header. **What can the relay credential do?** As the [scope matrix test](https://github.com/hamza-paracha/teslabot/blob/54dab29972209dfaeb010f4b223c72c5db6efcd7/tests/credential-scopes.test.ts#L80) shows, it can POST telemetry to `/telemetry/ingest`, not use the dashboard or MCP.
- **#9 — Reject writes after lease takeover.** Releasing a lock checked the owner, but a late write could still clobber a newer one. Now `Store.putMany` in [`src/storage/database.ts`](../src/storage/database.ts) checks all leases held by that Store in the write batch. The [nested-lock test](https://github.com/hamza-paracha/teslabot/blob/54dab29972209dfaeb010f4b223c72c5db6efcd7/tests/lease.test.ts#L64) shows that holding the inner lock cannot rescue a write after losing the outer one. **Why does token rotation still save after vehicle takeover?** `ownerToken` in [`src/tesla/auth.ts`](../src/tesla/auth.ts) uses a separate Store holding the account lease; Tesla has already spent the old refresh token.
- **#10 — Write down the trade-offs.** The rationale was spread through code and setup docs. The [ADRs](adr/README.md) collect the decisions, alternatives, limits and links to evidence. For example, open `currentSummary` in [`src/routes/vehicle.ts`](../src/routes/vehicle.ts) and the [parallel cold-read test](https://github.com/hamza-paracha/teslabot/blob/54dab29972209dfaeb010f4b223c72c5db6efcd7/tests/performance.test.ts#L31) behind ADR 002. **Did the ADR change the behavior?** No. The test checks the code; the ADR explains why the design is worth keeping.
- **#11 — Show write-failure recovery, not just describe it.** The trip demo did not show how ingest responds to a database failure. `runTelemetryRetry` in [`scripts/lib/demo-telemetry.ts`](../scripts/lib/demo-telemetry.ts) uses the real route and a local D1 trigger. The [retry demo test](https://github.com/hamza-paracha/teslabot/blob/54dab29972209dfaeb010f4b223c72c5db6efcd7/tests/demo.test.ts#L6) checks 503 then 200, the recovered write and the unchanged healthy account. **Does it run the relay container?** No. The demo resends the HTTP request itself; the relay suite checks the sender's retry loop.
- **#12 — Commit signup as one unit.** Previously a token write could fail after the account was created and the invite spent. Now `signUp` in [`src/routes/auth.ts`](../src/routes/auth.ts) puts the account, invite consumption and encrypted tokens in one D1 batch. The [signup write-failure test](https://github.com/hamza-paracha/teslabot/blob/54dab29972209dfaeb010f4b223c72c5db6efcd7/tests/accounts.test.ts#L241) shows that the invite stays unused and no account is created on failure. **Is the Tesla OAuth exchange part of that transaction?** No; the guarantee is about the local database changes.
- **#13 — Turn off live data without a local mapping.** Enable can configure Tesla and then lose its lease before saving the mapping; disable used to stop at the missing row. Now `disableTelemetry` in [`src/routes/telemetry.ts`](../src/routes/telemetry.ts) sends Tesla's DELETE for the selected car if the account has Tesla tokens, even without a local mapping. The [missing-mapping test](https://github.com/hamza-paracha/teslabot/blob/54dab29972209dfaeb010f4b223c72c5db6efcd7/tests/telemetry.test.ts#L695) shows the DELETE is sent even though the response says `removed: false`, which refers to the local mapping. **What if another account maps the car?** The unmapped account leaves it alone, as the [other-account test](https://github.com/hamza-paracha/teslabot/blob/54dab29972209dfaeb010f4b223c72c5db6efcd7/tests/telemetry.test.ts#L713) shows.
